## ЧАСТЬ 1. Почему были допущены ошибки на Mac (Строгие правила для модели Argon / любого ИИ)

На этапе написания прототипа на Mac (без доступа к установленной Dota 2) модель допустила классические ошибки ИИ-генерации. Ниже — **жесткие запреты**, которые агент на Windows обязан соблюдать:

1. **Запрет на синтетические тесты («Сам придумал формат — сам протестировал»):**
   - *Что произошло:* Для проверки парсера `.vmap` был написан юнит-тест со строкой `sample_kv2`, которую модель сама же и придумала (с 1 элементом без запятых и без вложенных `relayPlugData`/`connectionsData`).
   - *Правило на Windows:* Никаких выдуманных строк в тестах! Любой парсер (`.vmap`, `.kv`, `Decompiler.exe`) тестировать **только на реальном файле**, сконвертированном из `content/dota_addons/addon_template/maps/template_map.vmap` через настоящий `dmxconvert.exe`.
2. **Запрет на слепую замену текста регекспами (`count=1`) в древовидных форматах (DMX / KeyValues2):**
   - *Что произошло:* При клонировании `CMapEntity` заменялся только первый `"id" "elementid"`, а вложенные элементы сохраняли старые UUID донора.
   - *Правило на Windows:* В DMX/KeyValues2 **каждый** `"id" "elementid"` внутри клонируемого блока обязан получать новый `uuid.uuid4()`, а целочисленные `nodeID` должны инкрементироваться от максимума по карте.
3. **Запрет на использование консольных команд/флагов без проверки их реального вывода:**
   - *Что произошло:* Предполагалось, что `script_help2 <term>` фильтрует вывод, а `resourcecompiler -i map.vmap` сам собирает GridNav и мир.
   - *Правило на Windows:* Перед зашиванием любой CLI-команды (`dmxconvert`, `resourcecompiler`, `Decompiler`, `script_help2`) сначала выполнить её 1 раз в терминале на реальном файле Доты, посмотреть реальный `stdout`/`stderr` и созданные выходные файлы.

## ЧАСТЬ 2. Выявленные баги в коде (Что нужно починить на Windows в первую очередь)

### 🔴 Критичные (Сломают работу, чинить до первого запуска кастомки)

#### 🔴 1. `vmap_builder.py`: Синтаксис запятых в `element_array` (KeyValues2)
- **Файл:** [src/dota2_mcp/vmap_builder.py](../src/dota2_mcp/vmap_builder.py) (`add_map_entity`, `remove_map_entity`)
- **Суть бага:** В формате DMX `keyvalues2` элементы внутри `"children" "element_array" [ ... ]` **разделяются запятыми** (`,`), а после последнего элемента запятой быть не должно. Сейчас `add_map_entity` вставляет блок после донора без запятой, а `remove_map_entity` удаляет блок, не трогая соседнюю запятую (оставляя `}, ,` или висячую запятую перед `]`).
- **Как чинить на Windows:**
  1. Сконвертировать реальный `template_map.vmap` через `dmxconvert.exe -i ... -oe keyvalues2 -of vmap`.
  2. Посмотреть глазами точный разделитель между соседними `"CMapEntity"` внутри `"children" "element_array"`.
  3. Исправить `add_map_entity` (добавлять `,` перед вставляемым блоком, если вставляем после существующего элемента) и `remove_map_entity` (аккуратно удалять ведущую или завершающую запятую элемента).
  4. Проверить валидность результата обратной конвертацией через `dmxconvert.exe` — если `dmxconvert` возвращает код `0`, синтаксис KV2 гарантированно валиден!

#### 🔴 2. `vmap_builder.py`: Дублирование вложенных `elementid` и `nodeID` при клонировании `CMapEntity`
- **Файл:** [src/dota2_mcp/vmap_builder.py](../src/dota2_mcp/vmap_builder.py) (`add_map_entity`)
- **Суть бага:**
  1. `re.sub(..., count=1)` меняет только верхний UUID, оставляя дубликаты UUID у вложенных sub-elements (`relayPlugData`, `connectionsData` и др.).
  2. Поля `"nodeID" "int" "<N>"` не обновляются (два объекта получают одинаковый `nodeID` в Hammer).
  3. Если на карте нет `info_*`, донором может стать меш/триггер с дочерней геометрией.
- **Как чинить на Windows:**
  1. Из реального сконвертированного `template_map.vmap` вытащить эталонный чистый блок точечной сущности (`CMapEntity` от `info_player_start_goodguys`) и сохранить его как чистый шаблон (без мешей).
  2. При генерации новой сущности заменять **все** вхождения `"id" "elementid" "..."` через `re.sub(r'("id"\s+"elementid"\s+")[^"]+(")', lambda m: f"{m.group(1)}{uuid.uuid4()}{m.group(2)}", block)` (без `count=1`).
  3. Находить максимальный `"nodeID" "int" "(\d+)"` в файле карты и присваивать новой сущности `max_node_id + 1`.

#### 🔴 3. `netcon_bridge.py`: Конфликт порта `29000` с `vconsole2.exe`
- **Файл:** [src/dota2_mcp/netcon_bridge.py](../src/dota2_mcp/netcon_bridge.py), `README.md`, `TECHNICAL_SPEC.md`
- **Суть бага:** Порт `29000` по умолчанию занят бинарным протоколом `VConsole2` (который автоматически стартует вместе с `-tools`). Использование `-netconport 29000` приводит к конфликту портов или чтению бинарного мусора вместо текстового Telnet-потока.
- **Как чинить на Windows:**
  1. Изменить дефолтный порт в `netcon_bridge.py` (`DEFAULT_NETCON_PORT`) с `29000` на **`2121`** (или `29100`).
  2. В параметрах запуска Steam для Dota 2 использовать: `-tools -netconport 2121 -console -condebug`.

#### 🔴 4. `netcon_bridge.py`: `verify_vscript_api` и работа `script_help2`
- **Файл:** [src/dota2_mcp/netcon_bridge.py](../src/dota2_mcp/netcon_bridge.py)
- **Суть бага:** Консольная команда `script_help2` в Dota 2 может вываливать весь дамп API (тысячи строк), а `run_console_command` возвращает только последние 50 строк (`console_tail`), из-за чего нужная функция обрежется.
- **Как чинить на Windows:**
  1. В `verify_vscript_api(search_term)` фильтровать **весь** полученный буфер ответа `raw_output` (или читать `game/dota/console.log`) по подстроке `search_term.lower()` на стороне Python до обрезки до 50 строк!

## ЧАСТЬ 3. Гипотезы: что еще может пойти не так на Windows (и как это проверить)

1. **Гипотеза А: В `Source2Viewer-CLI` (`cli-windows-x64.zip`) исполняемый файл называется `Source2Viewer-CLI.exe`, а не `Decompiler.exe`.**
   - *Проверка:* В `config.py` уже добавлена проверка обоих имен, но при распаковке архива в `diagnostics.py` нужно убедиться, что бинарник не лежит во вложенной подпапке внутри `.zip`.
2. **Гипотеза Б: Блокировка файлов `.vmap` и `.vpk`, когда открыт Hammer Editor или сама Dota 2.**
   - *Почему может пойти не так:* На Windows открытый в Hammer файл `.vmap` может блокироваться на запись, либо Hammer перезапишет наши изменения при нажатии `Ctrl+S`.
   - *Защита:* Редактировать `.vmap` через MCP до открытия карты в Hammer (или компилировать через `resourcecompiler.exe` и сразу запускать в игре через `dota_launch_custom_game`, вообще не открывая окно Hammer).
3. **Гипотеза В: Кодировка и BOM в файлах локализации `addon_russian.txt`.**
   - *Почему может пойти не так:* Кириллица в `addon_russian.txt` в UTF-8 без BOM иногда отображается кракозябрами, если клиент Доты ожидает UTF-8 with BOM (`utf-8-sig`) или UCS-2 LE (`utf-16`).
   - *Проверка:* Проверить кодировку штатного файла в `game/dota_addons/addon_template/resource/addon_english.txt` на Windows и использовать точно такую же.
4. **Гипотеза Г: Таймаут `resourcecompiler.exe` при первой компиляции карты.**
   - *Почему может пойти не так:* Первая сборка карты (прогрев шейдеров и света) может занять 1–3 минуты.
   - *Защита:* Не прерывать процесс раньше 300 секунд и использовать быстрые флаги компиляции для тестовых итераций.
5. **Гипотеза Д: Консольная команда `dota_launch_custom_game` требует точного совпадения имени папки аддона в нижнем регистре.**
   - *Защита:* Всегда создавать `addon_name` только из строчных латинских букв, цифр и подчеркиваний (`^[a-z0-9_]+$`).

## ЧАСТЬ 4. Пошаговый алгоритм действий для агента на Windows (Выполнять строго по шагам!)

Когда пользователь напишет на Windows: *«Настрой проект / давай продолжим»*, агент обязан идти по этому чеклисту:

- **Шаг 1 (Окружение и Самодиагностика):**
  1. Создать `.venv`, установить `requirements.txt`.
  2. Запустить `.venv\Scripts\python -m src.dota2_mcp.diagnostics --bootstrap`, проверить пути к Dota 2 и скачивание `Decompiler` (`Source2Viewer-CLI.exe`).
- **Шаг 2 (Снятие реальных эталонов из установленной Dota 2):**
  1. Найти `content/dota_addons/addon_template/maps/template_map.vmap` и прогнать его через реальный `dmxconvert.exe` в текстовый файл во временной папке.
  2. Прочитать фрагмент реального текстового `.vmap` (как именно записаны `CMapEntity`, запятые в `element_array`, `nodeID`, `EditGameClassProps`).
  3. Запустить реальный `Source2Viewer-CLI.exe` на одной модели (`pudge.vmdl_c`) и одном партикле из `pak01_dir.vpk`, посмотреть формат их вывода.
- **Шаг 3 (Починка 🔴 1–4 и 🟠 5–11 в коде `src/dota2_mcp/`):**
  1. Починить `vmap_builder.py` по реальному шаблону `.vmap` и **доказать работоспособность**, прогнав измененный `.vmap` обратно через `dmxconvert.exe` и `resourcecompiler.exe`!
  2. Сменить порт NetCon на `2121`, починить фильтрацию в `verify_vscript_api`, `config.py`, `addon_manager.py`, `asset_inspector.py` и добавить поиск звуковых событий.
  3. Записать все найденные при реальном прогоне отличия в [docs/BUG_LOG.md](./BUG_LOG.md).
- **Шаг 4 (Подключение MCP и Боевой запуск):**
  1. Прописать сервер в `%USERPROFILE%\.gemini\config\mcp_config.json`.
  2. Сообщить пользователю, что система полностью проверена на реальных бинарниках Dota 2 и готова к созданию кастомки.
